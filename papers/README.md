# Exam paper builder

Static browser-local PDF question selector for Playground. No account, backend, OCR, API key or upload of source documents. Upload multiple PDFs, choose detected questions from each paper's dropdown, reorder them, and export a combined A4 paper. Manual rectangular selection remains available. Fictional example papers are generated locally.

## Behaviour and limits

- `detect.js` reads embedded PDF text positions, groups text into lines, and identifies numbered headings using their left gutter, numbering sequence and common formats. Supports plain numbers, starred OCR headings, explicit `Question 1` headings, AQA `01` / `01.1` labels and boxed digits extracted as separate text items. Subparts and repeated continuation headings are grouped under their top-level question.
- Detection estimates full-width regions between question starts, joins continuation pages, skips recognised blank pages, and stops at recognised end-of-paper markers. Running headers and footers are filtered where recognisable. It is heuristic, not a universal exam parser: unusual layouts, multi-column numbering, shared instructions and image-only headings can need correction. Check every section. PDFs without readable embedded text get a clear manual-selection fallback; no OCR is performed.
- Preview shows the first detected section. Add question imports all its detected sections, with source-page thumbnails and duplicate protection per source question. Use each section's View button to review it, adjust its crop, and choose Update viewed section to save a correction. Sections can also be removed or added manually.
- Manual selection supports pointer/touch dragging, whole pages or precise percentage coordinates. PDF.js renders in the source's displayed orientation, including rotation and CropBox handling. Fit-page and fit-width views do not change the selection coordinates.
- Question groups can contain multiple regions from any source pages. Regions stay in the order added; whole questions can be reordered. Source PDFs used by a question cannot be removed until those sections are removed.
- Each added question has **Choose question parts → Find question parts**. `subparts.js` reads letter labels such as `(a)` / `6(b)` and decimal labels such as `06.1`, and divides the existing selections into full-width bands. Untick parts to omit them, including their continuation pages, diagrams and answer spaces. Shared introductory material is retained; nested roman parts stay with their lettered parent. Roman-only questions can also be split. Original subpart labels are preserved, so check cross-references and dependencies between retained and omitted parts.
- Part choices are reversible while their controls remain available: checking every part restores the original selections. Marks are re-detected after a change (including resetting manual overrides), and recognised printed whole-question totals are removed from partial selections so they cannot override the retained allocations. Review the new marks total before export. Omitting every part is blocked; remove the whole question instead. Editing crops or adding/removing sections resets the choices against the remaining content. Sources retained for reversible omissions remain protected from removal.
- Subpart boundaries are heuristic and require readable PDF text. Use each retained section's View control to check the crop; use manual crops for scanned pages or unusual layouts. Shared diagrams located inside an omitted part need to be added manually if another part requires them. Omissions remove pixels from the output rather than covering them with white rectangles.
- An optional cover can use any page from any loaded paper. The tool locates a likely title, date, duration and total-marks line, including date/duration columns on the same baseline. Change the paper title, cover date and duration, and adjust replacement rectangles by dragging or entering percentages. Missing fields use clearly identified default positions. The preview shows the replacements; the export retains the rest of the source cover using the selected PDF format. Other exam codes, instructions and candidate-information fields remain unchanged and need review for the new paper. Covers can also be positioned manually for scanned pages.
- `marks.js` reads bracketed mark allocations (`[3]`, `[3 marks]`, `(3 marks)`) and explicit question totals from the selected regions. Question totals take precedence over their component allocations. Duplicate overlapping rows are counted once. Values, ambiguous layouts and unreadable scans can require correction: each question has an editable marks input and a Re-detect button. Automatic values recalculate after cropping/removing sections; manual overrides remain until reset. The displayed total is the sum of the current questions and updates on edits/removals.
- Cover marks always use that compiled total, not the source paper's maximum. A cover cannot be exported while a question's marks are unresolved or still being read. Papers without a cover can still export without allocations. Check detected marks before using a paper: OCR is not performed and the heuristic cannot establish every mark scheme's meaning.
- The PDF format selector defaults to **Editable text PDF**. `editable.js` captures visible native text while PDF.js paints each selected region, then emits real PDF text with its position, rotation, colour and width retained. Standard serif/sans/monospace fonts approximate source families, including bold/italic; common symbols use the PDF Symbol font. The cover uses the same text-preservation path, with original edited fields excluded before replacement. Select **Image PDF** for the original appearance-preserving raster export.
- Diagrams, scanned text, Type 3/path-drawn fonts, unsupported or ambiguous glyph mappings, and other unsupported text painting remain images. No OCR is performed. Editable output uses fixed-position text objects suitable for a PDF editor, rather than flowing word-processor paragraphs. Review unusual fonts, overlapping graphics, clipped text and equations; the image format remains available when appearance is more important than text editing.
- Both formats use selected-region PNG backgrounds rendered at 180 or 300 dpi and laid out on A4. In editable mode, supported text is removed during painting and drawn as PDF text over that background. Large regions scale down to fit the printable area. Render buffers are limited to 24 million pixels / 10,000 pixels per dimension, which can reduce resolution for exceptionally large source pages.
- Only selected crop pixels and supported painted text within the selection are embedded; whole source pages and hidden content outside the selection are not copied into the output. This is a question assembly tool, not a document redaction service. Supported text in editable mode can be selected, copied, searched and changed with a PDF editor. Image mode rasterises the question text. Neither mode creates a tagged accessible document. Scanned source quality cannot be improved by choosing a higher dpi.
- Renumbering is enabled by default and follows the current question-set order at export time. Added headings become `Question 1`, `Question 2`, etc. Detected source main numbers and decimal prefixes are replaced in the rendered question, including repeated continuation labels. Alphabetic/roman subparts and numerical values within the prose are left unchanged. AQA-style two-digit boxed numbers retain their leading-zero convention (source `16` becomes `03` for the third question).
- `numbering.js` locates leading digits in detected text rows, masks those digit glyphs on white backgrounds and adds replacement PDF text at their original positions. Existing box borders and decimal suffixes remain. Original source PDFs and the source viewer are unchanged. Text-run character widths are estimated from PDF widths/font metrics, so check the final preview with unusual fonts or layouts.
- Single-question manual crops containing recognised labels can also be renumbered. Image-only labels, clipped labels and manual crops containing multiple source questions retain their printed numbering. References such as “see question 16” within prose are not rewritten. You can turn renumbering off to preserve source labels and headings.
- "Remove left/right margins (enlarge questions)" removes the added 42 pt side margins and scales each question region to the full A4 width, including enlarging smaller regions. Scaling preserves aspect ratio and is limited by the available page height; height-limited regions are centred. Added labels and header/footer text retain an 18 pt inset. Covers are unchanged. Whitespace within source selections remains, and physical edge-to-edge printing requires printer support.
- Header and footer spacing defaults to Compact: a 10 pt title, a 48 pt top area (24 pt when the title is hidden), and a 32 pt bottom area with navigation and page numbers sharing one line. Choose None to omit the repeated title, divider, page numbers and footer notices and use 18 pt (about 6 mm) top/bottom margins. Question labels and incoming continuation headings remain controlled separately; covers are unchanged. Selected source whitespace is part of the image crop and can be reduced with the crop controls.
- The checked-by-default "Show paper title on question pages" option controls the repeated title and its divider. Turning it off leaves the cover title, PDF metadata, question labels, continuation notices and page numbers unchanged.
- Optional question headings, title, page numbers and source references use standard PDF fonts. Unsupported characters in those added labels are replaced with `?`; unsupported original question glyphs remain in their rendered images.
- `navigation.js` removes recognised source continuation, turn-over and end-of-paper notices from question crops, including wrapped notices. After layout, the exporter adds notices based on the actual output page breaks and current question numbers. Questions continuing onto another page receive an outgoing notice and an incoming continuation heading, even when ordinary question headings are disabled. Sections that now fit together on one page no longer carry their source continuation notices. Covers are left unchanged.
- Navigation notices require readable embedded text. Notices inside scanned images, unusual wording and other references within question prose need manual review. Only recognised notice rectangles are masked; nearby copyright text, diagrams and question content remain.
- Interactive forms, annotations, attachments and source document scripts are not included. PDF JavaScript actions are not executed. Password-protected PDFs are rejected.
- Limits: 20 source papers, 50 MB per file, 150 MB total, 500 pages per source and 200 selected regions. Work remains in memory and clears on refresh/navigation; download the output before leaving. Failed imports retain existing work. Export errors retain selections for retry.

## Dependencies

- Vendored Mozilla PDF.js / pdfjs-dist 6.5.438, Apache-2.0 (`vendor/PDFJS-LICENSE.txt`): https://mozilla.github.io/pdf.js/
- Vendored pdf-lib 1.17.1, MIT (`vendor/PDFLIB-LICENSE.txt`): https://pdf-lib.js.org/
- PDF.js loads supplemental character maps, standard font data and image-decoder WASM from the pinned jsDelivr distribution when required. Requests contain asset URLs, never source PDFs. Fonts used by the interface come from Google Fonts.
- The PDF.js version uses a separate page mapper for each document, allowing source papers and generated previews with different page counts to remain open together. Versioned module and worker filenames keep cached versions in sync.

Validation: `node tests/paper-builder.cjs` with the repository's local server running. Set `PLAYGROUND_URL` to run against a deployment. The test creates its own PDFs and checks multi-source assembly, continuations, ordering, scanned/rotated sources, crop pixel exclusion, output layout/dimensions, invalid files, downloads and mobile overflow.

Question indexing: `node tests/paper-question-detection.cjs` uses synthetic numbered papers, image-only PDFs, multi-page questions, starred headings and blank/end pages. It also tests dropdown additions, source switching, duplicate prevention, crop corrections and PDF downloads. If ignored fixtures `artifacts/ocr-paper-test.pdf` and `artifacts/aqa-paper-test.pdf` are present, it additionally checks the public OCR June 2023 H446/01 paper (7 main questions) and AQA June 2023 7408/1 paper (31 main questions). These exam-board files are not distributed with Playground.

Renumbering: `node tests/paper-renumbering.cjs` checks source Q16 → output Q3, decimal subparts, continuations, boxed digits, changes after reordering, switching renumbering off, and renumbering with added headings disabled. A pixel comparison verifies that erasing labels leaves the surrounding question/diagram unchanged. An optional public AQA fixture validates real boxed number locations.

Covers/marks: `node tests/paper-cover.cjs` checks source-cover artwork, edited fields, page selection, total-vs-subpart counting, editable allocations, missing-mark blocking, crop recalculation and cover removal. Optional public fixtures also verify complete totals of 85 (AQA) and 140 (OCR), and date/duration field separation.

Navigation: `node tests/paper-navigation.cjs` checks actual output page transitions, renumbering on/off, sections combined onto one page, wrapped notices, disabled question headings, generic manual selections and final end notices. Pixel comparisons check that notice removal preserves surrounding content. An optional public AQA fixture verifies a real continuation notice. Sources deliberately have different page counts to cover independent document lifetimes.

Spacing: `node tests/paper-spacing.cjs` exports full-height question regions through the UI with compact titles, hidden titles and no header/footer. Rendered PDF pixel bounds verify the reclaimed margins and unclipped content; extracted text verifies page numbers, titles and navigation are present only when enabled. A wide-region fixture verifies the optional zero side margins, enlargement beyond source size and preserved aspect ratio.

Subquestions: `node tests/paper-subparts.cjs` checks letter and decimal labels, keeping nested roman parts with their parent, multi-page omission, shared introduction/diagrams, updated marks and restoring all parts. Rendered output confirms that omitted content is absent and retained diagrams survive. Mobile overflow is also checked.

Editable PDFs: `node tests/paper-editable.cjs` verifies the default format, native searchable question text, source colours, common Greek symbols, rotated text, retained diagrams, absence of omitted/cropped text, and the image-format alternative. An optional public AQA fixture checks reconstruction from embedded source fonts. Existing cover, subquestion, renumbering and spacing tests run with the new UI default.
