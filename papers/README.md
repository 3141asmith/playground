# Exam paper builder

Static browser-local PDF question selector for Playground. No account, backend, OCR, API key or upload of source documents. Upload multiple PDFs, choose detected questions from each paper's dropdown, reorder them, and export a combined A4 paper. Manual rectangular selection remains available. Fictional example papers are generated locally.

## Behaviour and limits

- `detect.js` reads embedded PDF text positions, groups text into lines, and identifies numbered headings using their left gutter, numbering sequence and common formats. Supports plain numbers, starred OCR headings, explicit `Question 1` headings, AQA `01` / `01.1` labels and boxed digits extracted as separate text items. Subparts and repeated continuation headings are grouped under their top-level question.
- Detection estimates full-width regions between question starts, joins continuation pages, skips recognised blank pages, and stops at recognised end-of-paper markers. Running headers and footers are filtered where recognisable. It is heuristic, not a universal exam parser: unusual layouts, multi-column numbering, shared instructions and image-only headings can need correction. Check every section. PDFs without readable embedded text get a clear manual-selection fallback; no OCR is performed.
- Preview shows the first detected section. Add question imports all its detected sections, with source-page thumbnails and duplicate protection per source question. Use each section's View button to review it, adjust its crop, and choose Update viewed section to save a correction. Sections can also be removed or added manually.
- Manual selection supports pointer/touch dragging, whole pages or precise percentage coordinates. PDF.js renders in the source's displayed orientation, including rotation and CropBox handling. Fit-page and fit-width views do not change the selection coordinates.
- Question groups can contain multiple regions from any source pages. Regions stay in the order added; whole questions can be reordered. Source PDFs used by a question cannot be removed until those sections are removed.
- An optional cover can use any page from any loaded paper. The tool locates a likely title, date, duration and total-marks line, including date/duration columns on the same baseline. Change the paper title, cover date and duration, and adjust replacement rectangles by dragging or entering percentages. Missing fields use clearly identified default positions. The preview shows the replacements; the export retains the rest of the source cover as a rendered image. Other exam codes, instructions and candidate-information fields remain unchanged and need review for the new paper. Covers can also be positioned manually for scanned pages.
- `marks.js` reads bracketed mark allocations (`[3]`, `[3 marks]`, `(3 marks)`) and explicit question totals from the selected regions. Question totals take precedence over their component allocations. Duplicate overlapping rows are counted once. Values, ambiguous layouts and unreadable scans can require correction: each question has an editable marks input and a Re-detect button. Automatic values recalculate after cropping/removing sections; manual overrides remain until reset. The displayed total is the sum of the current questions and updates on edits/removals.
- Cover marks always use that compiled total, not the source paper's maximum. A cover cannot be exported while a question's marks are unresolved or still being read. Papers without a cover can still export without allocations. Check detected marks before using a paper: OCR is not performed and the heuristic cannot establish every mark scheme's meaning.
- Exports use PNG crops rendered at 180 or 300 dpi and laid out on A4. Large regions scale down to fit the printable area. Render buffers are limited to 24 million pixels / 10,000 pixels per dimension, which can reduce resolution for exceptionally large source pages.
- Only selected crop pixels are embedded; hidden content from outside the selection is not copied into the output. This is a question assembly tool, not a document redaction service. Question text is rasterised, so output is not text-searchable/editable or tagged for screen readers. Scanned source quality cannot be improved by choosing a higher dpi.
- Renumbering is enabled by default and follows the current question-set order at export time. Added headings become `Question 1`, `Question 2`, etc. Detected source main numbers and decimal prefixes are replaced in the rendered question, including repeated continuation labels. Alphabetic/roman subparts and numerical values within the prose are left unchanged. AQA-style two-digit boxed numbers retain their leading-zero convention (source `16` becomes `03` for the third question).
- `numbering.js` locates leading digits in detected text rows, masks those digit glyphs on white backgrounds and adds replacement PDF text at their original positions. Existing box borders and decimal suffixes remain. Original source PDFs and the source viewer are unchanged. Text-run character widths are estimated from PDF widths/font metrics, so check the final preview with unusual fonts or layouts.
- Single-question manual crops containing recognised labels can also be renumbered. Image-only labels, clipped labels and manual crops containing multiple source questions retain their printed numbering. References such as “see question 16” within prose are not rewritten. You can turn renumbering off to preserve source labels and headings.
- Optional question headings, title, page numbers and source references use standard PDF fonts. Unsupported characters in those added labels are replaced with `?`; original question glyphs are preserved in their rendered images.
- Interactive forms, annotations, attachments and source document scripts are not included. PDF JavaScript actions are not executed. Password-protected PDFs are rejected.
- Limits: 20 source papers, 50 MB per file, 150 MB total, 500 pages per source and 200 selected regions. Work remains in memory and clears on refresh/navigation; download the output before leaving. Failed imports retain existing work. Export errors retain selections for retry.

## Dependencies

- Vendored Mozilla PDF.js / pdfjs-dist 5.4.624, Apache-2.0 (`vendor/PDFJS-LICENSE.txt`): https://mozilla.github.io/pdf.js/
- Vendored pdf-lib 1.17.1, MIT (`vendor/PDFLIB-LICENSE.txt`): https://pdf-lib.js.org/
- PDF.js loads supplemental character maps, standard font data and image-decoder WASM from the pinned jsDelivr distribution when required. Requests contain asset URLs, never source PDFs. Fonts used by the interface come from Google Fonts.

Validation: `node tests/paper-builder.cjs` with the repository's local server running. Set `PLAYGROUND_URL` to run against a deployment. The test creates its own PDFs and checks multi-source assembly, continuations, ordering, scanned/rotated sources, crop pixel exclusion, output layout/dimensions, invalid files, downloads and mobile overflow.

Question indexing: `node tests/paper-question-detection.cjs` uses synthetic numbered papers, image-only PDFs, multi-page questions, starred headings and blank/end pages. It also tests dropdown additions, source switching, duplicate prevention, crop corrections and PDF downloads. If ignored fixtures `artifacts/ocr-paper-test.pdf` and `artifacts/aqa-paper-test.pdf` are present, it additionally checks the public OCR June 2023 H446/01 paper (7 main questions) and AQA June 2023 7408/1 paper (31 main questions). These exam-board files are not distributed with Playground.

Renumbering: `node tests/paper-renumbering.cjs` checks source Q16 → output Q3, decimal subparts, continuations, boxed digits, changes after reordering, switching renumbering off, and renumbering with added headings disabled. A pixel comparison verifies that erasing labels leaves the surrounding question/diagram unchanged. An optional public AQA fixture validates real boxed number locations.

Covers/marks: `node tests/paper-cover.cjs` checks source-cover artwork, edited fields, page selection, total-vs-subpart counting, editable allocations, missing-mark blocking, crop recalculation and cover removal. Optional public fixtures also verify complete totals of 85 (AQA) and 140 (OCR), and date/duration field separation.
