01 / KEEP WHAT MATTERS

Smaller files.
Different compromises.

Compression reduces the amount of data needed to represent something. Less data means less storage and, at the same transfer rate, a shorter transfer time.

LOSSLESS

Every detail comes back.

Represent patterns more efficiently, then reconstruct the original exactly. Essential when even a small change would alter meaning: program code, a spreadsheet or a text document.

LOSSY

Some detail is discarded.

Keep an approximation that is good enough for its purpose. Images, audio and video can trade fidelity for smaller representations. Discarded information cannot be recovered just by decompressing.

TRY IT / COLOUR QUANTISATION

How much detail can you lose?

01

Reduce the number of possible values for each red, green and blue channel. Look at the sky and the smooth gradients.

A quantisation model, not a JPEG encoder. Payload sizes assume tightly packed RGB channel values; metadata and further compression are excluded. Lower precision can help later compression. At 8 bits the representation is unchanged.

Make the distinction.

Lossless describes exact reconstruction, not a guarantee of a smaller file. Lossy methods discard information; repeatedly applying a lossy encoding can introduce further damage. A compressed file is not automatically encrypted.

Explain it in a scenario

A hospital needs an exact copy of a patient-data table, so use lossless compression. A small music preview can use lossy compression if the audible quality is acceptable. Link the choice to what must be preserved, rather than just naming a file extension.

02 / REPLACE REPETITION

A pattern is
an opportunity.

Both methods below are lossless. Run-length encoding exploits adjacent repetition; dictionary coding can reuse a sequence even when its occurrences are far apart.

What is included in the bit count?

This is an explicitly defined teaching format, not a claim about all dictionary compressors. Dictionary entries travel with the stream; omitting them gives a misleading saving. Real formats use different token rules and overheads.

When does it help?

RLE suits long runs such as a simple bitmap row. Alternating symbols can make it expand. Dictionary coding suits repeated sequences, including separated words, but its dictionary overhead may outweigh the benefit for short inputs.

03 / WHO HOLDS THE KEY?

Visible traffic.
Private meaning.

Encryption transforms plaintext into ciphertext using an algorithm and a key. An interceptor may copy the ciphertext; the aim is to prevent them recovering the plaintext without the right secret.

SYMMETRIC

One shared secret.

The same secret key encrypts and decrypts. Efficient for large amounts of data, but the parties need a secure way to establish that secret. Sending it openly beside the ciphertext defeats the purpose.

ASYMMETRIC

A related key pair.

For confidentiality, encrypt with the recipient's public key; decrypt with their corresponding private key. The public key can be distributed, but its ownership must be verified. The private key stays secret.

CIPHERTEXT / HEXNot encrypted yet.
Bob's recovered message—

The browser performs real AES-GCM (fresh IV) or RSA-OAEP encryption with temporary generated keys. This is a short-message demonstration; no message or key is sent to a server. AES output includes its authentication tag; the IV must also accompany the ciphertext. Never use a lesson input for sensitive data.

How can the two approaches work together?

A hybrid system uses asymmetric techniques to protect or establish a shared session secret, then uses symmetric encryption for the bulk data. This combines a manageable key-establishment process with efficient data encryption. Authenticating the parties or their public keys remains essential.

Do not swap the purpose.

Public-key encryption for confidentiality and digital signatures are different operations. A signature is made using a private key and checked using the corresponding public key; describing it simply as “encrypting the message with a private key” misses how real signature schemes work.

04 / A FINGERPRINT, NOT A SECRET MESSAGE

Same input.
Same fingerprint.

A hash function maps data to a value. A cryptographic hash produces a fixed-length digest and is designed to make reversing the mapping or finding collisions impractical. Hashing has no decryption key.

COMPARE / SHA-256

Change a character. Watch the bits.

05

SHA-256 gives 256 bits, displayed as 64 hexadecimal digits. Highlighted digits differ. A small input change typically changes many output bits; it does not guarantee every bit changes. The text is encoded as UTF-8.

INTEGRITY

Has the data changed?

Recompute a downloaded file's hash and compare it with a trusted expected digest. A difference shows the bytes differ. A match alone does not prove who made the file: an attacker who replaces both the file and its displayed hash could fool an unauthenticated comparison.

PASSWORD VERIFICATION

Compare without decrypting.

Password + unique salt↓Slow password-hashing function↓Store salt + derived value

At login, derive a value from the entered password using the stored salt and parameters, then compare. Salts prevent identical passwords sharing identical stored values and frustrate precomputed tables. Use a suitable password-hashing function: a single fast SHA-256 digest is not a suitable password-storage design.

LOCATE / HASH TABLES

A hash can point to a bucket.

06

Toy rule: add character codes, then take the remainder on division by 10. This is an indexing example, not a cryptographic hash. Duplicate keys are shown once.

Different keys can map to the same bucket: a collision. Here a bucket stores a chain of entries; a lookup still compares the full keys. Hash tables can provide fast average lookup, but collisions and a poor distribution can make them slower.

Fixed length does not mean unique.

There are more possible inputs than fixed-length digests, so collisions must exist. A useful cryptographic hash makes finding one difficult. A hash is not a compressed copy you can decode, and hashing does not keep the input confidential against guessing.

RETRIEVE / APPLY / EXPLAIN

What can you
explain now?

Eight original questions. Commit to an answer, then check the reasoning. These are practice activities, not an OCR past paper or mark scheme.

Explain: why might RLE make a file bigger?

Each run needs a symbol and a count. With mostly single-symbol runs, that extra count costs space without replacing much repetition. State the supplied storage assumptions, calculate both sizes and compare them.

Explain: how would you send a large confidential file to a new recipient?

One approach is to authenticate the recipient's public key, use asymmetric encryption to protect a fresh shared session key, and encrypt the large file symmetrically. Only the corresponding private key should recover the session key. Use an appropriate authenticated scheme and explain how keys are trusted.
