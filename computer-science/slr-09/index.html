01 / KEEP WHAT MATTERS

Smaller files.
Different compromises.

Compression changes how data is represented so that it can use fewer bits. This can reduce both the space needed to store a file and the time needed to transmit it. The key question is whether decoding can recover the original exactly or only produce an approximation.

LOSSLESS

Every detail comes back.

Lossless compression records the same information in a form that can be decoded exactly. This makes it suitable for data such as program code or a spreadsheet, where removing even one character or changing one value could alter its meaning.

LOSSY

Some detail is discarded.

Lossy compression makes a smaller representation by discarding some information. It can suit images, audio or video when an approximation is acceptable for the intended use, but decoding cannot recover the details that were removed.

Make the distinction.

Judge a method first by what decoding recovers: lossless preserves the original exactly, whereas lossy discards information. The amount of space saved depends on the data and format, so exact recovery does not guarantee a smaller file. Compression also serves a different purpose from encryption: reducing size does not by itself keep the content secret.

Explain it in a scenario

A hospital must preserve every value in a patient-data table, so it needs lossless compression. A short music preview has a different requirement: a smaller lossy version may be suitable if its audible quality is acceptable. In each case, the reason for the choice is what the user needs to recover, rather than the name of the file extension.

02 / REPLACE REPETITION

A pattern is
an opportunity.

Both methods below preserve the original data, but they describe different kinds of repetition. Run-length encoding counts consecutive copies of one symbol, while dictionary coding replaces recurring sequences with references. Following how each method decodes its output explains why both are lossless.

What is included in the bit count?

The dictionary travels with the stream in this teaching format, so both must be included when calculating the saving. Counting only the references would leave out information the decoder needs. Other formats may use different token rules or overheads, so always apply the assumptions supplied for the particular question.

When does it help?

RLE is useful when many consecutive symbols can be replaced by a small number of pairs, as in a simple bitmap row. Alternating symbols offer no long runs and can therefore make the encoded result larger. Dictionary coding can exploit repetitions in separate places, but it must save enough through reuse to cover the cost of its dictionary.

03 / WHO HOLDS THE KEY?

Visible traffic.
Private meaning.

Encryption lets a sender protect a readable message, called plaintext, by turning it into ciphertext using an algorithm and a key. An observer may still copy the ciphertext, but should be unable to recover the plaintext without the required secret. The recipient uses the appropriate key to decrypt it.

SYMMETRIC

One shared secret.

The sender and recipient use the same secret key to encrypt and decrypt the message. This is efficient for large amounts of data, but both parties must first obtain the shared key securely. Anyone who copies that key as well as the ciphertext could also recover the message.

ASYMMETRIC

A related key pair.

The recipient has a related public/private key pair and keeps the private key secret. A sender encrypts using the recipient’s public key, allowing the recipient to decrypt with the matching private key. The sender must also verify whose public key they have obtained, so the message is protected for the intended person.

How can the two approaches work together?

A hybrid system combines the strengths of both approaches. It uses an appropriate asymmetric technique to establish or protect a shared session secret, then uses that secret with symmetric encryption for the main data. This supports efficient encryption of large files while addressing how the parties obtain their shared secret; verifying the relevant identities or public keys remains part of the process.

Do not swap the purpose.

For a confidential message, the sender encrypts with the recipient’s public key and the recipient decrypts with their private key. A digital signature has a different purpose and key arrangement: a signer creates it with a signing private key, and others check it with the corresponding public key. Keep these operations distinct rather than describing a signature as simply encrypting a message backwards.

04 / A FINGERPRINT, NOT A SECRET MESSAGE

Same input.
Same fingerprint.

A hash function turns input data into a value that can be calculated again for comparison. A cryptographic hash produces a fixed-length digest, often described as a fingerprint of the input. This supports checks on the data, but the digest cannot be decrypted to recover the original.

INTEGRITY

Has the data changed?

After downloading a file, calculate its hash and compare it with an expected digest obtained through a trusted route. If they differ, the downloaded bytes differ from the expected version. The trust requirement matters because an attacker who can replace both the file and its displayed digest could supply a matching pair.

LOCATE / HASH TABLES

A hash can point to a bucket.

06

This indexing example adds the character codes in a key and takes the remainder on division by 10 to choose a bucket. The rule is deliberately simple so you can predict collisions; it is not a cryptographic hash. Duplicate keys are displayed once.

When different keys map to the same bucket, they collide. This model keeps a chain of entries in that bucket, so a lookup can compare the full keys and select the correct entry. Hash tables can provide fast average lookup, but a poor distribution leaves more entries to compare and reduces that benefit.

Fixed length does not mean unique.

A fixed-length digest has fewer possible values than the full range of possible inputs, so some different inputs must share an output. A suitable cryptographic hash makes finding such collisions difficult. That practical protection supports its uses, but does not make the digest a reversible copy or stop someone from testing guesses for a likely input.

Explain: why might RLE make a file bigger?

Each run needs space for both its count and its symbol. When most runs contain only one symbol, the count adds storage without replacing useful repetition, so the encoded result can be larger. To demonstrate this, apply the supplied field sizes to both the original and encoded forms, then compare their totals.

Explain: how would you send a large confidential file to a new recipient?

One approach is to verify the recipient’s public key and use an appropriate asymmetric scheme to protect a fresh symmetric session key. The recipient recovers that key using the matching private key, and both parties then use the shared secret to protect the large file with authenticated symmetric encryption. This combines secure key establishment with efficient bulk encryption; the explanation must also show why the public key is trusted.
